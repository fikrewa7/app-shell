BlobDB Documentation

Complete specification and API reference for the Blob Image & Video Database dashboard.

Version: 2.0.0

Status: Active

Last Updated: August 31, 2026

Images

Manage image collections with folder cards and slideshow.

Videos

Upload, preview, and play videos with custom controls.

Folder Cards

Top-level folders display random image previews and counts.

Technology Stack

Frontend

  • HTML5 – Semantic markup and structure
  • Vanilla JavaScript – No framework dependencies
  • Tailwind CSS – Utility-first styling via CDN
  • Font Awesome 6.4.0 – Icon library
  • Web Crypto API – PBKDF2 + AES-GCM encryption

Backend API

  • Endpoint: https://blob-img-db.vercel.app/api
  • Auth: Bearer token (API Secret Key)
  • Protocol: REST over HTTPS
  • Upload: Multipart form data (FormData)

Storage & Caching

  • localStorage – Stores encrypted API key and cached blob data
  • Blob Store – Remote storage with path-based hierarchy
  • Cache – First fetch cached; invalidated after upload/delete

API Reference

Fetch Blobs

GET

/blobs

Retrieve all blobs (images and videos) from the store. The client filters based on mode.

GET /blobs?_=timestamp HTTP/1.1
Host: blob-img-db.vercel.app/api
Authorization: Bearer YOUR_SECRET_KEY

Response (200 OK):

{
  "blobs": [
    {
      "pathname": "uploads/screenshots/2026/08/30/photo.jpg",
      "url": "https://...",
      "downloadUrl": "https://...",
      "size": 245678,
      "uploadedAt": "2026-08-30T12:34:56Z",
      "lastModified": "2026-08-30T12:34:56Z",
      "type": "image/jpeg"
    },
    {
      "pathname": "uploads/videos/2026/08/30/movie.mp4",
      "url": "https://...",
      "downloadUrl": "https://...",
      "size": 567890,
      "uploadedAt": "2026-08-30T12:34:56Z",
      "lastModified": "2026-08-30T12:34:56Z",
      "type": "video/mp4"
    }
  ],
  "storeId": "store_abc123"
}

Upload File

POST

/uploads?category=category&lastModified=timestamp

Upload a file (image or video). For videos, thumbnails are also uploaded to the same category with a /thumbnails suffix.

POST /uploads?category=videos/2026/08/30 HTTP/1.1
Host: blob-img-db.vercel.app/api
Authorization: Bearer YOUR_SECRET_KEY
Content-Type: multipart/form-data

image: [File]
lastModified: 1693382096000

Response (200/201 OK):

{ "success": true, "pathname": "uploads/..." }

Delete Blob

DELETE

/blobs

Delete a blob by pathname. For videos, the thumbnail should also be deleted.

DELETE /blobs HTTP/1.1
Host: blob-img-db.vercel.app/api
Authorization: Bearer YOUR_SECRET_KEY
Content-Type: application/json

{ "pathname": "uploads/videos/2026/08/30/movie.mp4" }

Response (200 OK):

{ "success": true }

Test Connection

GET

/blobs?limit=1

Test API connectivity without fetching full dataset.

GET /blobs?limit=1 HTTP/1.1
Host: blob-img-db.vercel.app/api
Authorization: Bearer YOUR_SECRET_KEY

Response (200 OK):

{ "connected": true, "storeId": "store_abc123" }

Core Modules

ImageDB

Handles image-specific operations. Filters out videos and skipped folders.

Key Methods:

  • configure(options) – Set API base, key, category
  • fetchImages() – Fetch all blobs (with cache)
  • uploadFiles(files, onProgress, categories) – Upload images
  • deleteImage(pathname) – Remove image
  • testConnection() – Verify API access
  • addFiles(files) – Add to selection (deduped)
  • getSelectedFiles() – Get pending uploads
  • openSlideshow(index, urls) – Start image viewer
  • on(event, callback) – Register event listener

VideoDB

Handles video-specific operations, including thumbnail generation and custom player.

Key Methods:

  • configure(options) – Set API base, key, category
  • fetchVideos() – Fetch all blobs (with cache)
  • uploadFiles(files, onProgress, categories) – Upload videos with thumbnails
  • deleteVideo(pathname) – Remove video
  • testConnection() – Verify API access
  • generateThumbnailFromFile(file, callback) – Create thumbnail from video
  • openSlideshow(index, urls) – Start video player
  • on(event, callback) – Register event listener

FolderExplorer

Virtual filesystem abstraction. Builds a tree structure from flat blob paths and enables folder navigation.

Key Methods:

  • create(data) – Factory method
  • navigateToFolder(pathParts) – Change directory
  • getCurrentPath() – Get path array
  • getChildFolders(pathParts) – List subfolders
  • getFilesInCurrentFolder() – Get files
  • getAllFiles() – Return all blobs
  • searchFiles(query) – Find by name
  • getTotalStats() – Store statistics
  • formatSize(bytes) – Human-readable size

BlobUtils

Shared helper functions for both apps: formatting, filtering, caching, and folder helpers.

Key Functions:

  • isSkippedPath(pathname) – Excludes json / json-data
  • isVideoPath(pathname) – Excludes uploads/videos / uploads/video
  • getTopLevelFolders(blobs, basePath) – Returns allowed top‑level folder names
  • getRandomBlobsFromFolders(blobs, basePath, count) – Returns { folder: { total, images } }
  • saveCache(key, data) / loadCache(key) / clearCache(key) – localStorage cache utilities
  • createEmitter(prefix) – Custom event emitter
  • formatFileSize(bytes) – Human-readable size
  • formatDuration(seconds) – Video duration formatting

KeyEncryptor

Client-side encryption/decryption for API keys. Uses PBKDF2 key derivation and AES-256-GCM.

Methods:

  • encrypt(plaintext, password) → {iv, salt, ciphertext}
  • decrypt(bundle, password) → plaintext

Note: Uses async crypto.subtle API. Always use await or .then().

Event System

Both ImageDB and VideoDB use a custom event emitter. Listen with ImageDB.on(event, callback) or VideoDB.on(event, callback).

imagesLoading / videosLoading

Fired when fetch begins.

imagesLoaded / videosLoaded data: {images/videos, count, storeId, fromCache}

Data successfully fetched (or loaded from cache).

imagesFetchError / videosFetchError data: {error, message}

Fetch failed.

uploadStarted data: {total, files}

Upload batch initiated.

uploadProgress data: {overallPercent, ...}

Upload progress update.

uploadComplete data: {success, total, failed}

Upload finished. Cache is cleared automatically.

selectionChanged data: {selectedFiles, count}

File selection updated.

slideshowOpened, slideshowChanged, slideshowClosed

Slideshow state changes.

connectionTested data: {connected, storeId, message}

API test result.

Security & Encryption

API Authentication

All API requests use Bearer token authentication.

Authorization: Bearer <API_SECRET_KEY>

The key is stored in localStorage after decryption on app load.

Unlock Flow (PBKDF2 + AES-GCM)

  1. User enters a password on first load
  2. Password is used to derive a key via PBKDF2-SHA256 (600,000 iterations)
  3. Derived key decrypts embedded cipher with AES-256-GCM
  4. Decrypted API key is stored in localStorage
  5. Page reloads and app initializes with stored key
// Embedded encrypted key structure:
_jfrKey = {
  iv: "base64_encoded_iv",
  salt: "base64_encoded_salt",
  ciphertext: "base64_encoded_ciphertext"
}

⚠️ Important Security Notes

  • API key lives in localStorage – only accessible to same origin
  • Always use HTTPS in production to prevent man-in-the-middle attacks
  • Browser console can access localStorage – assume compromised if attacker has console access
  • For sensitive environments, consider server-side key management

Usage Examples

1. Initialize & Configure (Both Apps)

// Configure ImageDB
ImageDB.configure({
  apiBase: 'https://blob-img-db.vercel.app/api',
  apiSecretKey: 'your-secret-key',
  uploadCategory: 'screenshots'
});

// Configure VideoDB
VideoDB.configure({
  apiBase: 'https://blob-img-db.vercel.app/api',
  apiSecretKey: 'your-secret-key',
  uploadCategory: 'videos'
});

// Listen for events
ImageDB.on('imagesLoaded', function(data) {
  console.log('Loaded', data.count, 'images, from cache:', data.fromCache);
});
VideoDB.on('videosLoaded', function(data) {
  console.log('Loaded', data.count, 'videos, from cache:', data.fromCache);
});

2. Fetch & Browse with Folder Cards

// Fetch images
ImageDB.fetchImages().then(function(images) {
  // Use BlobUtils to get top-level folder data
  const folderData = BlobUtils.getRandomBlobsFromFolders(images, 'uploads', 3);
  console.log(folderData);
  // Output: { "screenshots": { total: 82, images: [...] }, ... }
});

// Or use FolderExplorer for deeper navigation
const explorer = FolderExplorer.create({
  blobs: ImageDB.getImages(),
  storeId: ImageDB.getStoreId()
});
explorer.navigateToFolder(['uploads']);
const topFolders = explorer.getChildFolders(['uploads']);
console.log(topFolders); // ["screenshots", "camera", ...]

3. Upload Images and Videos

// Upload images
const imageFiles = document.getElementById('file-input').files;
ImageDB.addFiles(imageFiles);
ImageDB.uploadFiles(ImageDB.getSelectedFiles(), null, ['screenshots/2026/08/30']);

// Upload videos (with thumbnails)
const videoFiles = document.getElementById('file-input').files;
VideoDB.addFiles(videoFiles);
VideoDB.uploadFiles(VideoDB.getSelectedFiles(), null, ['videos/2026/08/30']);

4. Delete & Manage

// Delete an image
ImageDB.deleteImage('uploads/screenshots/2026/08/30/photo.jpg')
  .then(() => ImageDB.fetchImages());

// Delete a video and its thumbnail
const videoPath = 'uploads/videos/2026/08/30/movie.mp4';
const thumbPath = videoPath.replace('/videos/', '/videos/thumbnails/').replace(/\.[^.]+$/, '.jpg');
VideoDB.deleteVideo(thumbPath)
  .catch(() => {}) // ignore if thumbnail missing
  .then(() => VideoDB.deleteVideo(videoPath))
  .then(() => VideoDB.fetchVideos());

5. Encryption & Password Unlock

// Encrypt an API key with a password
const password = 'my-secure-password';
KeyEncryptor.encrypt('my-api-secret-key', password)
  .then(bundle => console.log('Encrypted:', bundle));

// Decrypt with password
const bundle = {
  iv: 'a4EroL5JUEgVloj1',
  salt: 'PtvozUTEvgxEqQUpQY3yyA==',
  ciphertext: 'ne2yiSgFCpDpDbjMmcW4wlNoFo2ogXbhH2sPHFup9Sv...'
};
KeyEncryptor.decrypt(bundle, 'my-secure-password')
  .then(decrypted => console.log('API Key:', decrypted))
  .catch(err => console.error('Wrong password:', err.message));

Application Architecture

Data Flow

┌─────────────────────────────────────────────────┐
│ User Browser (Client)                           │
├─────────────────────────────────────────────────┤
│ index.html                                      │
│  ├─ blobDB.js        (all modules)              │
│  │   ├─ KeyEncryptor (crypto)                   │
│  │   ├─ BlobUtils    (helpers + cache)          │
│  │   ├─ FolderExplorer (navigation)             │
│  │   ├─ ImageDB      (image API)                │
│  │   ├─ VideoDB      (video API)                │
│  │   └─ ImageDBApp / VideoDBApp (UI init)       │
│  ├─ Tailwind CSS     (styling)                  │
│  └─ localStorage: encrypted key + cache         │
└────────────────┬────────────────────────────────┘
                 │ HTTPS
                 ├─ GET /blobs
                 ├─ POST /uploads (multipart)
                 ├─ DELETE /blobs
                 └─ GET /blobs?limit=1 (test)
                 │
            ┌────▼──────────────────────────┐
            │ Backend API (blob-img-db)      │
            ├────────────────────────────────┤
            │ Vercel Deployment              │
            │ - Auth: Bearer token           │
            │ - Storage: Blob store          │
            │ - Response: JSON               │
            └────────────────────────────────┘

App Startup & Mode Switching

  1. Determine app mode (image or video) from localStorage
  2. If no stored API key → show unlock modal, decrypt with password
  3. Store decrypted key in localStorage
  4. Configure the appropriate DB module
  5. Check cache → if present, load data immediately; otherwise fetch from API
  6. Build folder tree and render gallery (folder cards at top level)
  7. Attach event listeners for upload, delete, settings
  8. Switch button updates localStorage and reloads

Caching Strategy

  • First successful fetch saves blob list to localStorage under imageDB_cache_v1 or videoDB_cache_v1
  • Subsequent page loads use cache immediately, avoiding network delay
  • After upload or delete, cache is cleared automatically
  • Manual refresh button also clears cache before refetching
